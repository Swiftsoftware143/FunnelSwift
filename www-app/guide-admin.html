🏢 Tenant & Plan Management

The Super Admin dashboard at /admin provides full control over tenants (workspaces), plans, and feature assignments. You must be logged in as the root super admin.

Tenant List

Shows all tenants with their current plan assignment, creation date, and status. You can:

  • Assign Plan — Click "Plan" on any tenant row to select a plan from the dropdown
  • View Details — Click a tenant name to see full info
  • Disable — Toggle tenant active/inactive

💳 Plans & Feature Toggles

Plans define what each tenant can access. Navigate to /admin/plans to manage them. Each plan has a set of feature toggles stored as JSONB:

Feature registry — every gated key

Every gate in the app reads its key through ONE registry (src/feature_registry.rs), and the operator surface for it is the Plans & Features view in the admin console.

Absence is not refusal for a numeric limit. A limit with no feature_limits row and a NULL plans column is “not configured”, and the gate then allows the action — that key enforces nothing (it is inert) until a number is set. A boolean is the opposite: an absent features jsonb key falls back to the has_* column, whose default is false, so absence refuses. That is why the top tier's grant has to exist as data, not as an assumption.

Feature registry matrix (in the panel)

The Plans & Features view renders one row per registry key and one column per plan, showing the value the gate will actually see (not merely what a row stores):

  • ✅ / ❌ — a boolean: granted / refused.
  • ∞ — a limit set to -1: unlimited.
  • off — a limit set to 0: not available on that plan (a 402).
  • a number — the cap.
  • unset — no row and no column: the gate allows by absence. The line under the table lists those keys for the top tier.
  • ★ marks the top tier (the highest price — never assumed from the name).

Click any cell to change that one entitlement on that one plan: type true/false for a boolean, or a number for a limit (-1 unlimited, 0 off, blank clears the row). The save re-reads the value through the same resolver the gate uses, so the answer you get back is the trade the app will enforce.

Grant everything to the top tier fills the top plan's gaps: every registry limit with no row gets -1 and every boolean not already on is turned on. It never raises a cap you set yourself, so it is safe to press again after a new key or a new plan is added. The status line above the table reports whether any other plan beats the top tier on any key — that is what “the top tier gets everything” actually means, and it is checked, not assumed.

Affiliates: max_affiliates is 1 on every plan (one affiliate account per customer, enforced by a unique index) and is deliberately not part of the “unlimited” grant.

🔒 Template Gating

Control which templates each plan can access. Templates are gated per plan using an allowed_template_ids array on the plans table.

How It Works

  • NULL — Plan sees ALL 54 templates (Pro, Enterprise default)
  • Empty array [] — Plan sees ZERO templates (effectively locked)
  • List of IDs — Plan sees ONLY those specific templates

API Endpoints

GET  /api/v1/admin/plans/:id/templates   — View allowed templates for a plan
PUT  /api/v1/admin/plans/:id/templates   — Set allowed templates

Example: Give Free plan 8 templates

curl -X PUT https://funnelswift.net/api/v1/admin/plans/{plan_id}/templates \
  -H "Content-Type: application/json" \
  -d '{"allowed_template_ids":[
    "starter_biz_card","starter_bio_link",
    "starter_mini_page","starter_mini_funnel",
    "blank_biz_card","blank_bio_link",
    "blank_mini_page","blank_mini_funnel"
  ]}'

Example: Unlock all templates

curl -X PUT https://funnelswift.net/api/v1/admin/plans/{plan_id}/templates \
  -H "Content-Type: application/json" \
  -d '{"allowed_template_ids":null}'

🏷️ Branding Badge Toggle

The branded badge ("Claim your free Digital Business Card →") appears on every public card page unless the tenant turns it off.

Rules

  • Free plan: Branding badge is always shown — cannot be hidden
  • Paid plans (Pro, Enterprise): Tenant can toggle branding badge OFF in their settings
  • Affiliate link: If tenant has an affiliate_code, the badge URL includes ?ref={code} — tracking clicks through their affiliate account
  • Card type aware: Badge text changes automatically: "Digital Business Card", "Bio Link", "Mini Page", "Mini Funnel"

Tenant Toggle (for paid plans)

Tenants can hide branding by setting a flag in their workspace settings:

// Tenant Settings JSON
{
  "hide_branding_badge": true
}

When true and on a paid plan, the branding badge disappears. Affiliates who want referral clicks should leave this OFF.

Why Keep Branding On?

Paid tenants who are also affiliates benefit from keeping branding ON — the badge links to funnelswift.net/kinetic?ref={their_code}, giving them referral credit for every signup that comes through their card.

🏷️ System Tags

What Are System Tags?

A System Tag is a tag an admin creates once and every tenant can see and use. A regular tag belongs only to the account that made it; a System Tag appears in every account's Tags list. Only an admin can create, rename, recolor or delete one.

What They Do Not Do

Assigning a System Tag to a lead does not create accounts, contacts or clients in other Swift apps. FunnelSwift has no per-tag target and no provisioning webhook: this app has no system_tags table, and the System Tag form holds a name, a tag group and a color — nothing to point at another app.

How It Works

  1. Admin creates a System Tag — Super Admin → Tags → System Tags → + Add System Tag (name, tag group, color)
  2. Every tenant sees it — it appears in each account's Tags list alongside that account's own tags
  3. Admin-managed — Edit renames or recolors it for every tenant at once; Del removes it for every tenant. A tenant cannot change or delete it.

🤝 Affiliate Management

Your account is the control centre, not an affiliate

Open My Affiliate in the sidebar. As an admin you get a control centre: live counts of affiliates, commission tiers, payouts and products, plus buttons that take you straight to each screen. You are never asked to sign up as an affiliate — you run the programme, affiliates join it themselves.

One affiliate account per customer

A customer account can have exactly one affiliate account, on every plan including the free ones. This is enforced by the database, so coming through a different path cannot create a second one. There is no downline and no hierarchy — an affiliate is paid directly, and there is nothing to recruit.

Affiliate Products

Define what affiliates can promote. Each product has a name, description, price, commission rate, and optional tracking URL.

Every product must point at a FREE plan. This is the rule that stops an affiliate giving a product away fully upgraded for nothing: a referred customer arrives on the free plan and upgrades in app, paying for it themselves. The database refuses to attach a paid plan to a product or a tag, so this cannot be got wrong from any screen.

Each product is also tied to its tag. The tag is what actually credits the affiliate when a referral arrives, so a product without a tag can be picked in the portal but can never be credited — the affiliate's screen says so plainly.

Affiliate Tiers

Create commission tiers (Bronze, Silver, Gold, etc.). Each tier has exactly four editable values:

  • Name — what the tier is called
  • Commission Rate (%) — what an affiliate earns once they reach the tier
  • Min Sales — how many sales are needed to reach it
  • Min Revenue — how much revenue is needed to reach it

Everything is editable — change a rate, rename a tier or delete one at any time. Bronze / Silver / Gold are seeded as placeholders with sensible rates; adjust them to your own numbers whenever you like.

Where it lives: admin.funnelswift.net → Commission Tiers in the sidebar (the app console at app.funnelswift.net has the same screen under Affiliate Tiers). Saved values are what you typed — if you enter 12.5%, the tier stores 12.5%.

Commission Groups

Commission Groups in the admin sidebar is how you give several products one rate without changing them one at a time: tick the products that should be treated the same, enter a single rate, and create the group. A group rate then sits above each product's own rate in the order above.

The same screen has a “set a rate for selected products” box for changing one product's own rate, or several at once, without making a group. Deleting a group never deletes its products — they simply go back to their own rates.

What rate an affiliate is paid

One order decides it, and the first rule that applies wins. The order is fixed, and every recorded commission stores the rate and which rule produced it, so a payout can still be explained months later after the rates have changed.

#RuleWhere you set it
1A personal rate for that one affiliate — beats everything elseAffiliates → the affiliate's own rate
2A commission group rate — one rate covering several productsCommission Groups
3The product's own rateAffiliate Products
4The affiliate's own standing rate — set on their account when they joinedAffiliates
5The plan's rate the product is tied toPlans
6A standard fallback of 20% when nothing above is set—

Steps 1–3 are the three you control day to day; 4–6 exist so an affiliate always has a rate rather than none. A higher group rate therefore beats a product's own rate, and a personal rate beats all of it — which is what makes “give this one person more” work without disturbing anyone else.

What a commission goes through

A commission has a life, and each stage is dated: it starts pending while the referred customer is on a free plan (nothing is earned yet), becomes earned the day that customer moves onto a plan they pay for, and becomes reversed if they later leave a paying plan. A cancellation or a downgrade is therefore visible rather than silent, and a customer who comes back is credited again as a new dated entry. Payouts are separate: marking a commission paid does not change what was earned.

Nothing is paid on a free plan. A referral only starts earning when that customer becomes a paying customer, and the credit stays with the referring affiliate from then on.

Affiliate Leads

This screen is the record of everyone the programme actually produced. Each row is one lead, and the Affiliate column is the affiliate who gets credited for them — resolved from the credit stamped on the lead itself, so the column can never disagree with who gets paid.

System in that column means nobody is credited. That is the honest answer for a lead that arrived with no affiliate behind it (a direct signup, or a form with no tag): it is shown rather than hidden, so you can see the traffic the programme is not earning on.

The Became an affiliate column tells you whether the lead themselves later joined the programme — matched on their email address, and it stays true even years later. The Commission column shows what that lead has earned and whether it is still pending. The counts across the top cover the whole programme, not just the page you are looking at.

The Plan / last movement column is the one to watch: it shows the plan the referred person is on right now, and the date of their last movement — "Upgraded 3 Oct 2026", "Downgraded 11 Nov 2026". An upgrade credits the affiliate on the day it happens, and the same date appears on the affiliate's own dashboard, which reads the same record. A downgrade reverses the commission and records its own date, so a shrinking number can always be explained months later. The headline counts include how many referrals have upgraded and how many have downgraded.

Leads are matched into this screen three ways: they came through an affiliate's form, they carry the referring account on the record itself, or they carry a product's tag. That means a tagged lead still appears even if the stamp is somehow missing — the tag alone is enough to be counted.

Taking payments (Stripe)

FunnelSwift uses Stripe. Two things are needed, and both live on the Payment providers panel in the admin console:

  1. Secret key — the sk_live_… (or sk_test_…) key from your Stripe dashboard.
  2. Webhook signing secret — the whsec_… value Stripe shows for the endpoint you register.

Register this endpoint in Stripe (Developers → Webhooks → Add endpoint), and subscribe it to checkout.session.completed, customer.subscription.deleted and checkout.session.expired:

https://app.funnelswift.net/api/v1/webhooks/stripe

Both keys are required. Until the signing secret is saved, every payment notification is refused with the reason recorded, and the panel's table shows the secret as Missing rather than looking complete. Payments are only ever believed when they arrive signed; a forged or replayed notification changes nothing. Leaving either field blank when you save keeps the value already stored, so you can correct one without re-pasting the other.

What happens on a real payment: the customer's plan changes, the day is recorded, and the affiliate who referred them is credited on that same date — visible on both this console's Affiliate Leads screen and the affiliate's own dashboard. If the subscription later ends, the customer drops to the free plan of that same product and the affiliate's commission is reversed, dated.

Affiliate Portal

Affiliates log in at /affiliate to see their dashboard, leads/conversions, earnings and referral links. In the main app, the sidebar's My Affiliate tab is where they tick the products they want to promote.

🃏 Kinetic Template Management

Template Library

54 templates are served from /api/v1/kinetic/templates across 5 archetypes and dozens of industry niches. Templates are defined in src/handlers/theme_endpoint.rs and deployed as part of the binary.

Each template contains:

  • layout_blocks — The UI structure (avatar, title, CTA, services, reviews, etc.)
  • theme_key — Which theme to use (cyber_dark, ghost_white, ocean, forest, sunset, ruby, midnight, arctic)
  • gradient — CSS gradient string for the background
  • preview_colors — 3-color palette for the gallery thumbnail
  • niche — Industry/trade classification

❓ FAQ

Q: How do I add new templates?

Edit src/handlers/theme_endpoint.rs and add a new JSON object to the template array. Follow the existing schema for layout_blocks. Deploy with cargo build --release and systemctl restart funnelswift.

Q: Can a Free plan user see paid templates?

No. The template picker filters based on allowed_template_ids. Free plan users only see the 8 templates assigned to them. The API respects this gating.

Q: How does the branding badge know what card type to show?

The render_card handler reads template_type from the database and maps it to a human label: "Digital Business Card", "Bio Link", "Mini Page", or "Mini Funnel". It also checks the tenant's plan for white_label status and whether they've toggled hiding.

Q: What if the webhook fails?

The tag still records in FunnelSwift but the target app won't create the account. Re-assign the tag to retry.
